Timeline & Scheduling

Scheduling algorithms and timeline generation for cruise planning.

cruiseplan.timeline package.

This package contains scheduling and timeline generation modules for cruise planning:

  • record: the timeline record (ActivityRecord) and Timeline

  • distance: Geographic distance calculations using Haversine formula

  • duration: Time duration calculations for cruise operations and activities

  • scheduler: Core scheduling logic for generating cruise timelines

These modules provide the mathematical and algorithmic foundation for determining distances, durations and scheduling sequences in oceanographic cruises.

cruiseplan.timeline.record module

The timeline record: one scheduled activity, and the timeline type.

Every stage after the scheduler works from ActivityRecord: the writers (CSV, HTML, LaTeX, KML, NetCDF, maps) and the forecast, which reads records back from the NetCDF schedule.

cruiseplan.timeline.scheduler.apply_delays(timeline: list[ActivityRecord], leg_delays: Mapping[str, float] | None = None, first_leg: str | None = None, insert_waits: bool = True) → list[ActivityRecord][source]

Apply each operation’s delay_start_minutes.

A positive delay is waiting before the operation starts (for weather, a daylight start, …). It becomes its own wait record at the operation’s position, just before it, so no other record gets longer.

A negative delay means the operation started earlier than planned. The time comes out of the transit into the operation first (it was faster), then, if the delay is longer than that transit, out of the operation before it (it ended early). An actual duration never goes below zero; the part that cannot be absorbed is dropped, with a warning that says how to start the leg earlier when the leg start is reached. A negative delay is a quick fix and always warns: setting transit_minutes or duration_minutes on the record that was actually shorter states what happened.

planned_duration_minutes keeps the plan; duration_minutes is the actual duration. Within a leg every record starts where the one before it ends; between legs the leg delay is kept.

Parameters:

  • timeline (Timeline) – Records in schedule order, before delays are applied.

  • leg_delays (Mapping of str to float, optional) – Leg-level delay_start_minutes by leg name, used in the warning. When not given, it is taken from the gap before the leg.

  • first_leg (str, optional) – Name of the cruise’s first leg, used in the warning. When not given, the leg of the first record is taken as the first leg.

  • insert_waits (bool, optional) – Add a wait record for each positive delay (default). With False the wait is left as a gap before the operation, which keeps the record count (used for schedules read from older files).

Returns:

A new list with actual durations and times.

Return type:

Timeline
